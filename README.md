# BOSScript

boss 直聘批量「立即沟通」油猴脚本 —— **受控版 v1.1**

> 原始版本为无节制的 `window.open` 扇出，已被本次改造替换。改造依据见 [ANALYSIS.md](./ANALYSIS.md)。

## 它做了什么

列表页收集职位 → 去重过滤 → 进队列 → 按并发上限逐个打开详情页 → 详情页只点一次「立即沟通」→ 确认状态后自行关闭 → 结果回写主控面板 → 队列空了自动翻页。

与旧版的关键区别：

| 维度 | 旧版 v0.1 | 受控版 v1.1 |
|---|---|---|
| 开窗方式 | 同步 `forEach` 一次开几十个 | 并发池 ≤2，间隔 1.5-3s 随机 |
| 点击 | 每秒重复点 | 全流程只点一次（幂等） |
| 关闭时机 | 看到弹窗就关，可能中断请求 | 确认状态变化 + 最小稳定期后关 |
| 异常 | 抛错后轮询永不停止 | 异常必达 `clearInterval`，双端硬超时 |
| 去重/过滤 | 无 | 按 jobId 去重 + 历史排除 + 关键词白名单 |
| 配额 | 无，几秒打光 | 每日 20 次上限（可配） |
| 翻页 | 无 | 队列空自动翻页（页数可配） |
| 复盘 | 无 | 记录持久化 + CSV 导出 |
| 控制 | 无 | 面板可暂停/停止，全局刹车 |
| 注入范围 | 全站 `/*` | 仅列表页与详情页 |

## 使用方法

1. 新建油猴脚本，把 `instant.js` 全量粘贴进去保存。
2. 打开列表页，例如
   `https://www.zhipin.com/web/geek/job?query=前端&city=101020100&experience=102`
3. 页面左侧出现 **BOSS 批量沟通** 面板 → 点「开始」。
4. 浏览器若拦截新标签页，面板会明确提示「新标签页被浏览器拦截」，
   此时在地址栏右侧允许 `zhipin.com` 弹窗，再点「开始」即可。

> 注意：只有**首次**开窗处于用户点击手势内，后续开窗依赖站点弹窗白名单。
> 脚本不会掩盖这一点——被拦截就停机报告，不会假装在跑。

## 配置

全部集中在 `instant.js` 顶部 `CONFIG`：

| 键 | 默认 | 说明 |
|---|---|---|
| `concurrency` | 2 | 同时打开的详情页数量，建议 1-2 |
| `minGapMs` / `maxGapMs` | 1500 / 3000 | 开窗间隔随机区间 |
| `dailyLimit` | 20 | 每日成功沟通上限，跨天自动归零 |
| `maxTasksPerRun` | 30 | 单轮最多处理任务数 |
| `taskTimeoutMs` | 25000 | 主控侧单任务超时 |
| `workerDeadlineMs` | 18000 | 详情页侧整体超时 |
| `minSettleMs` | 1200 | 点击后最小等待，避免中断飞行中的请求 |
| `keywords` | `[]` | 职位关键词白名单，空=不过滤，例 `['前端','React']` |
| `skipCardText` | 已投递/已沟通/… | 命中即跳过 |
| `pagination.enabled` | `true` | 队列空时自动点「下一页」 |
| `pagination.maxPages` | 3 | 最多翻几页（不含首页） |
| `pagination.waitMs` | 6000 | 翻页后等待列表刷新的上限 |
| `network.enabled` | `false` | 接口级成功判定开关 |
| `network.urlPattern` | `''` | 沟通接口 URL 片段，例 `chat/start` |
| `network.log` | `false` | 把所有 xhr/fetch URL 打到控制台，用于抓包 |
| `sel.*` | — | 全部选择器，站点改版只改这里 |

## 自动翻页

队列排空且没有进行中任务时，脚本会自动点击「下一页」继续收集，直到 `maxPages`、`maxTasksPerRun` 或每日配额任一触顶。翻页后以「列表首条 jobId 是否变化」判断刷新完成，`waitMs` 内无变化即结束本轮——不会空转。

跨页去重由两层保证：`Records`（历史成功/已沟通）与 `planned`（本轮已入队），后者同时同步进执行器白名单。

## 导出记录

面板「导出记录」按钮把历史记录导成 CSV（带 BOM，Excel 直接打开不乱码）。字段：jobId、职位、状态、原因、时间、链接。记录上限 500 条，超出按时间淘汰最旧的。

## 接口级判定（可选，默认关闭）

DOM 判定（弹窗出现 / 按钮文案变「继续沟通」）够用但间接。若想更准：

1. 把 `CONFIG.network.log = true`，刷新列表页点开始，在控制台看 `[BOS] xhr open` / `[BOS] fetch` 输出；
2. 找到点击「立即沟通」时发出的那个请求，取它 URL 里的稳定片段（如 `chat/start`）；
3. 填进 `CONFIG.network.urlPattern`，并把 `network.enabled` 置 `true`。

命中 pattern 且返回 2xx 即判定成功，优先于 DOM 信号。脚本只**读**响应状态码，不修改、不重放任何请求。
